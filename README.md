# 竞彩预测统计 · 基础版

已上线：**https://ronald9527.github.io/jc-tj/**
直达最终确认：https://ronald9527.github.io/jc-tj/#confirm

## 这是什么

纯静态站点（HTML / CSS / JS，零依赖），网页与手机 App 同源：
手机浏览器打开链接 →「添加到主屏幕 / 安装应用」，就是独立图标、全屏运行，
和网页读同一套界面。PWA 清单 + Service Worker 让它断网也能打开。

- 竞彩足球（第 1 页）：今日赛程 / 港澳赔率 / 强弱对战 / 混合过关 / 高手推荐 / 比分预测
- 竞彩篮球（第 2 页）：同样的 6 个 Tab，顶部按钮互切
- 6 个 Tab 与日期条在手机上都排成网格，不左右滑动
- 混合过关可勾选、自动算组合赔率与预估回报
- 最终确认区列出「已做基础 / 后续逐步添加」

## 今日赛程的数据口径

**数据源：500 彩票网竞彩足球页**（国内站），实测 GitHub Actions 出口可直连，
0 元、免 key。按销售日抓取：`https://live.500.com/jczq.php?e=YYYY-MM-DD`。

页面表格直接含：**竞彩编号（`周日001` 这种）**、赛事、轮次、开赛时间、中文队名、
让球、亚盘盘口、全场比分、半场比分、胜平负赛果、状态。全部原样照抄，
不混其他赛事、不臆造编号。按编号前缀周几分组显示；前缀是**竞彩销售日**周几，
可能与开赛日期不同（如 `周日009` 在 11-16 凌晨开赛）。

### 赔率（页面内嵌 `liveOddsList`）

500 页面把赔率放在一个 JS 变量 `var liveOddsList = {...}` 里，按比赛 fid 索引，
不在表格单元格里（所以表格那一列看起来是空的）。解析后每场带：

| 字段 | 含义 |
|---|---|
| `sp` | 竞彩官方**胜平负奖金**（胜/平/负固定奖金） |
| `rqsp` | 竞彩官方**让球奖金**（让球胜/平/负） |
| `0` | 平均欧赔 |
| `5` / `293` / `280` / `3` / `1055` | 澳* / 威*** / 皇* / 36* / 另一家 |

`sp` 已核对与体彩官网固定奖金一致（例：中国 vs 马来西亚 `1.45/3.95/5.10`）。
个别场次官方未开售胜平负，`sp` 为空，页面显示「—」，不编造数字。

**赛果卡片**展示：全场比分（大字）、赛果、让球结果、半场、盘口，
下面三行赔率：胜平负奖金、让球奖金、平均欧赔。

### 全部玩法固定奖金

每张卡片底部有「全部玩法赔率」折叠按钮，展开后是竞彩官方
`trade.500.com/jczq/index.php?playid=...&date=销售日` 的四套玩法页数据，
全部照抄、按 `data-fixtureid` 与主赛程关联：

| 玩法 | playid | 内容 |
|---|---|---|
| 让球胜平负 | 269 | 页面 `spf`（与 `rqsp` 一致） |
| 总进球 | 270 | `jqs`：0 / 1 / 2 … 7+ 球，8 项 |
| 比分 | 271 | `bf`：31 项，按主胜 / 平局 / 客胜分组 |
| 半全场 | 272 | `bqc`：9 项（胜胜 … 负负） |

页面里 `nspf` 是胜平负、`spf` 是让球胜平负（命名反直觉，按实际奖金值核对过）。
已完赛场次会**自动高亮中奖项**（按全场/半场比分推算，仅标记，不改原赔率）。
历史较久的销售期 500 可能不再保留玩法页，此时面板如实提示「已过期」，不编造。

### 港澳赔率 Tab（只留香港 / 澳门）

数据源是 500 竞彩页的即时指数接口：
`https://live.500.com/json/odds.php?fid=比赛ID&cid=公司ID`。
返回 `[亚盘, 欧赔, 大小球]` 三组，每组 `[初盘 f, 当前 e]` 各 3 项；
500 自身用 `e - f < 0` 判「降水」、`> 0` 判「升水」，本站沿用该口径。

| 栏位 | cid | 500 页面标识 |
|---|---|---|
| 澳门 | 5 | 「澳*」 |
| 香港 | 3 | 默认参考盘「Be****」 |

接口对非 5 的 cid 一律回落默认，因此**免费源可稳定区分的只有这两家**；
500 免费源未提供独立「香港马会」盘口，页面第二栏已如实标注为默认参考盘，
不冒充香港马会数据。每场同时展示欧赔（胜/平/负）、亚盘、大小球的
**初盘 → 当前**与逐项 ↓降水 / ↑升水；当两家在欧赔同一项同时降水时，
卡片会加「⚠ 港澳同步降水」提示。与竞彩官方固定奖金是两套口径，页面已注明。

港澳 Tab 与今日赛程共用日期切换条，可回看各销售日盘口。

### 强弱对战（真实数据模型）

每场 `intel` 字段由服务端按 500 的真实数据算出，前端只展示：

| 因素 | 数据源 | 权重 |
|---|---|---|
| 联赛排名 | `live.500.com/detail.php?fid=` 当前排名 / `liansai.500.com/zuqiu-{sid}/` 积分榜 | 25% |
| 赛季积分率 | 联赛积分榜（赛/胜/平/负/积分） | 25% |
| 胜平负奖金隐含概率 | 竞彩官方固定奖金，1/奖金 归一化 | 35% |
| 近 5 场真实战绩 | `history.json` 里同队真实赛果，按 500 球队 ID 聚合；不足 3 场不计入 | 15% |

缺失因素自动剔除并重归一权重，页面逐项列出权重与主客数值，口径透明。
杯赛 / 国家队赛事（欧国联、友谊赛等）没有联赛积分榜，改用详情页排名，页面如实标注。
当综合分方向与官方奖金隐含方向相反时，标签改为「多因素分歧」，不硬套「强队打弱队」。
附加真实情报：上赛季排名变化、预计首发阵容、赛后技术统计（射门/角球/红黄牌）、
联赛主客场场均进球、港澳同步降水异动。

**伤停 / 停赛名单：500 免费源未提供，页面明确标注「未计入」，不编造。**

### 6 个 Tab 都有历史数据

所有 Tab 共用 `history.json` 的按销售日归档和同一个日期切换组件（`state.histDay` 全局）：

| Tab | 真实数据 | 历史能力 |
|---|---|---|
| 今日赛程 | 编号/赛果/全部玩法奖金 | 按日回看赛果 |
| 港澳赔率 | 初盘→当前、降水 | 按日回看盘口 |
| 强弱对战 | 积分榜/情报/强弱模型 | 按日回看强弱分 |
| 混合过关 | 官方胜平负奖金 | 按日回看并自动标命中 |
| 高手推荐 | 改为数据模型参考（非真人荐单） | 按日统计命中率 |
| 比分预测 | 31 项比分奖金反推概率 | 按日回看并高亮实际比分 |

竞彩篮球页 6 个 Tab 同样挂日期条，但篮球真实数据源尚未接入，页面如实标注为框架占位。

### 混合过关：庄家视角指标与 2串1~4串1 精选

服务端 `build_market()` / `build_parlay_recs()` 用 **6 家公司真实赔率 + 竞彩官方固定奖金 +
港澳盘口 + 联赛场均进球 + 真实赛果 + 强弱情报** 推导，全部写进 `history.json`
（每天 `market` 字段与 `parlay_recs`），前端只展示。

| 用户要的项 | 本站实现口径 |
|---|---|
| 庄家视角 / 凯利方差 | ∑1/官方奖金 = 庄家水位；K = 官方奖金 × 各公司去水隐含概率，跨公司取方差 |
| 离散数据 / 离散分歧 | 6 家公司隐含概率的变异系数 CV，分低/中/高分歧 |
| 凯利寻胆 | K 值最低的结果 |
| 泊松分布 | μ = 60% 近况攻守均值 + 40% 联赛主/客场场均进球，算 0–8 球矩阵 |
| 历史同指 / 同指精选 | 官方胜赔 ±0.18 的历史已完赛场次赛果分布，样本 ≥3 才下结论 |
| 五维雷达 / 差异分析 | 排名积分、近况、奖金隐含、盘口支撑、泊松五维；奖金 vs 泊松 vs 模型对照 |
| 冷热偏差 / 冷门预警 | 奖金隐含 − 泊松；离散高、方向相反、同步降水时告警 |
| 市场异动 / 走势寻踪 / 罗盘定位 / 异动赛事 | 港澳初盘→当前逐项变盘、同步降水、方向标签 |
| 球队情报 / 极限战绩 | 详情页排名、预计首发、技术统计、真实赛果里的最大比分与连胜连败 |
| 大数据 | 本站归档 7 个销售日 60 场真实赛果 + 6 家公司赔率 |

**明确无法提供（页面如实标注，不编造）**：必发指数 / 必发倾向（Betfair 成交量与成交价
需付费源）、伤停身价（500 免费源无伤停名单与球员身价）、外部「市场高精度预测模型」。
实测 `odds.500.com` 对机房 IP 拒绝访问，投注页只有凯利指数 UI 选项、不含数值接口。

**精选串关**：每场按「综合概率 = 50% 奖金隐含 + 30% 泊松 + 20% 强弱模型 − 离散惩罚」
取最高项（奖金隐含 ≥28%），按概率降序组成 2串1 / 3串1 / 4串1 各一组，
给出每腿**当前赔率**、组合赔率、联合概率、期望指数、置信度与风险标签。
未开赛场次优先，不足 4 场时用已完赛补足并标注「历史回测」。

> 全部为数据模型筛选演示，**不是高精度预测，不构成投注建议**；不接投注跳转、不做付费荐单。

### 完赛后赛果自动回填

定时任务（北京时间 06:00 / 12:00 / 18:00 / 00:00，每天 4 次）抓到某场状态为
「已完成」且有全场比分时，`fill_results()` 自动按竞彩官方口径回填并写入
`history.json` / `data.json`，前端不需要任何操作：

| 字段 | 口径 |
|---|---|
| `full` / `half` | 全场、半场比分（500 页面原样） |
| `result` | 胜平负：全场 90 分钟（含伤停补时，不含加时/点球）不让球 |
| `result_rq` | 让球胜平负：全场比分 ＋ 主队让球数，再判胜/平/负 |
| `result_bqc` | 半全场：半场胜平负 ＋ 全场胜平负，如「胜胜」「负平」 |
| `result_jqs` | 总进球：全场双方进球合计，7 球及以上归「7+ 球」 |
| `result_bf` | 比分：按竞彩 31 项标准，未列明的归「胜其它 / 平其它 / 负其它」 |

`results` 数组同时带上每项的**官方固定奖金中奖值**（从该场玩法页按标签精确匹配），
`settled` 标记是否回填，`settled_at` 记录首次回填时间（后续刷新不覆盖）。
页面在已完赛卡片上显示「✅ 赛果已自动回填」和六格明细；玩法面板里中奖项继续高亮。

只写赛果字段，**不修改任何赔率、盘口、球队情报原始数据**。欧洲凌晨赛事一般在
06:00 那一轮即可回填，最长约 6 小时。

**6 个 Tab 全部同步展示回填**（前端 `settledBlock()` 统一组件，服务端 `results` 优先、
旧数据用 `playHits()` 前端推算兜底）：

| Tab | 回填位置 |
|---|---|
| 今日赛程 | 每场卡片底部六格直接展开 |
| 港澳赔率 | 每场盘口卡片底部，可折叠展开 |
| 强弱对战 | 情报面板之后，可折叠展开 |
| 混合过关 | 逐场模型指标之后、自选勾选项之前；精选串关已完赛腿标注回填状态 |
| 高手推荐 | 模型倾向卡底部，可折叠展开 |
| 比分预测 | 比分概率列表之后，可折叠展开；无比分奖金的已完赛场次也保留回填卡片 |

4 个用 `tabData()` 的 Tab 页首还会显示「本页 N 场已回填六项赛果」。
竞彩篮球页仍为框架占位，不会混入足球赛果。Service Worker 缓存版本随前端改动递增，
主屏 App 无需重装即可拿到新版。

### 串关回溯：命中 / 未命中

`build_parlay_recs()` 对每组 2串1 / 3串1 / 4串1 的每一腿写入：

| 字段 | 含义 |
|---|---|
| `hit` | `true` 命中 / `false` 未命中 / `null` 未开赛，按「所选选项 === 实际胜平负赛果」判定 |
| `sel` / `result` / `full` / `half` | 选了什么、实际赛果、全场/半场比分 |
| `sel_prize` | 所选选项的竞彩官方固定奖金（命中即按它派奖） |
| `rq_result` / `bqc` / `jqs` / `bf` | 该场六项回填摘要，说明「实际发生了什么」 |
| `settled_at` | 该场首次回填时间 |

组合层面写入 `parlay_hit`（全中 / 未全中 / 待开赛）、`hit_legs` / `miss_legs` /
`pending_legs`、`hit_note`、`return_2yuan`（仅全中时给 2 元本金回报）。

口径：**串关必须所有腿都命中才算全中，任一腿未中即未全中**；部分腿完赛且暂无未中时
标「待开赛（已完赛 N/M 腿且全部命中）」。历史销售日的精选按当日真实赛果重新回溯，
所以切到 11-10 ~ 11-15 任意一天，三组串关都会直接给出命中结论。

前端 `recCard()` 把组合命中结论放在卡片最上方并配色（绿=全中 / 红=未全中 / 灰=待开赛），
每腿用「选 X → 实际 Y」链条 + ✓命中 / ✗未命中徽章，下面附六项赛果回填行。
逐场卡片另加「本场入选精选」行和一行式赛果小结，避免回填信息埋在折叠面板里看不明白。

### 高质量选腿：不再盲目堆低赔

旧版按综合概率降序取最高项，结果全是 1.11 / 1.24 / 1.31 这类稳胆，
2串1 组合赔率仅 **1.38**、4串1 仅 **2.58**——命中率高但性价比极低。
`build_parlay_recs()` 改为按「价值 × 质量」选腿：

| 规则 | 口径 |
|---|---|
| 单腿赔率 | **1.40–2.80**，排除超低赔稳胆与纯博冷 |
| 硬门槛 | 综合概率 ≥38%、市场隐含 ≥26%、离散 CV ≤10、≥2 条真实信号、模型与盘口不相反 |
| 价值分 EV | 当前赔率 × 综合概率 ÷ 100，即每 1 元期望回报 |
| 质量分 | 0.5×EV×100 + 0.3×综合概率 + 0.2×信号分 − 离散惩罚，需 ≥40 |
| 组合目标带 | 2串1 2.20–5.00 / 3串1 3.60–10.00 / 4串1 6.00–18.00 |
| 校准 | 低于下限用高价值候补换掉最低赔腿；高于上限换掉最高赔腿防博冷 |
| 宁缺毋滥 | 达标候选不足 n 场时直接写「无法组成」，不硬凑低赔或低质场次 |

真实信号只认可核验的五项：凯利寻胆、历史同指（样本 ≥3）、泊松首位、离散低、
港澳同步降水。每腿展示价值分、质量分、信号条数与离散 CV，卡片顶部展示组合赔率
是否落在目标带、平均价值与平均质量。

改版后今日示例：2串1 **2.62**、3串1 **4.82**、4串1 **7.47**，单腿赔率 1.55 / 1.69 /
1.84 / 1.55，均带 2–4 条真实信号；不再是 1.1 出头的稳胆堆叠。

**诚实标注**：历史销售日的精选是「用当前模型对当日历史数据做的回溯模拟」，
不是当时实时发出的推荐；命中 / 未命中只用于检验模型，不代表历史实盘。
模型改版后历史回溯结论会随之变化，页面页首已写明。

### 带日期的历史数据

- 「今日赛程」顶部有**日期切换条**（网格排列，手机不横滑），
  默认今天，可点开最近若干销售日查看当时的赛程、赛果与赔率。
- `history.json` 按 `?e=YYYY-MM-DD` 归档，每天 06:00 / 12:00 / 18:00 / 00:00 自动重抓滚动更新，
  抓不到的日期沿用上次成功结果；页面自报销售日用于去重，避免同一期重复归档。
- 页面打开时还会后台并发探测 9 条**竞彩官方**通道：哪天访客网络能通，
  就自动升级成「竞彩官网赛程（实时取数）」，状态条有「刷新官网」按钮。
  官方域名对机房 IP 一律 HTTP 567，所以服务端定时任务不依赖它。

其余 Tab（强弱对战、混合过关、高手推荐、比分预测）与篮球页仍为演示占位
数据，在 `index.html` 的 `DB` 对象里，后续逐步接。演示数据请勿用于付费荐单、
投注跳转或代购。

## 怎么更新

**不用上传、不用重装 App、不用重新加主屏幕。**
在这个对话里说一句要改什么，站点会被直接写入本仓库，约 1 分钟自动重新发布；
刷新页面就是新版。

## 登录与数据加密（2026-11-16 启用）

### 为什么要做

改版前站点是 **GitHub Pages 纯静态 + 公开仓库**：链接任何人能打开，
`data.json` / `history.json` 是明文直链，仓库源码和 git 历史也全公开，
不需要任何账号就能拿到全部赛程、赔率、赛果。加一个"前端登录框"挡不住
直接访问 JSON，所以改成**数据本身加密**。

### 现在的结构

| 项 | 位置 | 是否公开可见 |
|---|---|---|
| 账号 `admin` | 前端常量（账号不是秘密） | 可见 |
| 密码 | **GitHub Actions Secret `SITE_PASS`** | 不可见，不进源码/日志/提交 |
| 派生密钥 | PBKDF2-HMAC-SHA256(`admin\0密码`, 固定盐, 210000 轮) | 不存储 |
| 数据文件 | `data.enc` / `history.enc`（AES-256-GCM 密文） | 可下载但不可读 |
| 明文 `data.json` / `history.json` | 已从仓库删除 | — |

- 页面打开 → 输入账号密码 → WebCrypto 派生密钥 → 解密两个 `.enc` → 渲染。
- 密码不写在 `index.html` 里；解密失败即提示账号或密码错误，不解锁。
- 勾选「记住此设备 7 天」时，只把**派生出的密钥**存 localStorage（不是密码），
  7 天过期；不勾则存 sessionStorage，关掉标签失效。header 有「退出登录」。
- 定时任务用 Secret 派生同一密钥加密输出；Secret 缺失时**跳过本轮输出**，
  保留已有密文，绝不写明文兜底。
- Service Worker 只缓存密文，不缓存解密结果。

### 诚实的安全边界

1. **这不是服务端账号系统**：没有会话、没有权限分级、所有人共用 `admin`。
   纯静态托管做不到真鉴权；要那一级需要 Cloudflare Workers / Access 之类
   带服务端的免费层，需另做一次授权。
2. **链接本身仍公开**：任何人都能打开登录页、下载 `.enc` 密文。密码是 9 位
   纯数字，理论上可被离线暴力猜解（PBKDF2 210000 轮大幅抬高成本，但不是
   不可破）。**建议以后换成更长的随机密码**，且不要在其他网站复用这个号码。
3. **历史明文**：本次已用无父提交重建 `main`，常规访问路径下 git 历史里
   不再有明文数据文件；但 GitHub 对不可达对象可能短期仍保留缓存，
   改版前那几天的历史赛程数据应视为已经公开过。加密只能保护「从现在起」
   的新数据和当前入口。
4. **分享方式变了**：把链接发给别人时，需要一并把账号密码给对方；
   想恢复成公开可读，说一声即可撤掉。
5. 忘记密码：密码在 Secret 里，可重新派生密钥、重跑定时任务恢复；
   若改密码，需重新加密全量数据并由所有人重新登录。

### 改密码

在仓库 Settings → Secrets and variables → Actions 更新 `SITE_PASS`，
然后手动触发一次 `update-schedule` 工作流重新加密；旧密文随即失效，
所有设备会提示重新登录。密码不要发到聊天里、不要写进任何文件。

## 11-17 历史销售日丢失与恢复（2026-11-18）

**现象**：11-18 11:20 那轮自动更新后，日期条从 `11-18` 直接跳到 `11-16`，
`2026-11-17 周二` 整期消失。

**根因**（`data.json` 的 probe 里留有证据）：

```
请求 2026-11-17 | 页面自报 2026-11-18 | 行数 8
tried: e → TimeoutError（读超时）
       default → http 200，返回「当前期」11-18 的 8 场
```

旧 `grab_day()` 在 `?e=YYYY-MM-DD` 超时后回落到不带参数的默认页，
而默认页是**当前销售期**；页面自报的销售日变成 `2026-11-18`，
与当天那一轮 key 相同，被 `seen` 去重当作「重复期」跳过，
于是 17 号既没被归档，也没被兜底保留。

**修复**（`fetch_schedule.py`）：

1. `?e=` 读超时**重试 3 次**（超时 18 / 24 / 30 秒递增），降低偶发失败。
2. **历史日期禁止回落默认页**——只有 `day == TODAY` 才允许 `default` 通道，
   从源头杜绝「当前期冒充历史日」。
3. 万一页面自报销售日与请求日不符：优先沿用 `prev_days[本日]` 的上次成功归档；
   没有归档就本轮不写入并记 `drop`，**绝不冒充、绝不误去重**。
4. 兜底统一按**请求日** `day` 查 `prev_days`，不再按页面自报的 `real` 查。
5. 历史窗口 `DAYS` 从 8 扩到 **10**，滚动时不挤掉展示过的早期销售日。

**恢复**：从仓库历史提交 `f40e4889`（11-18 07:16 快照）取回 11-17 的
10 场完整归档（当时 9 场已回填），并从 `6de90ef2` 取回 11-10 的 2 场，
合并进当前 `history.enc` 作基线；随后触发工作流重抓，
`?e=2026-11-17` 第 1 次尝试即 200、10 场全部重抓成功，
**周二010 智利 vs 哥伦比亚 0:0 平**也补齐了赛果。

**现状**：9 个销售日 `11-18 ~ 11-10`，其中 11-17 为 10 场、
赛果回填 10/10、玩法赔率 10/10、港澳盘口 10/10，6 个 Tab 按日期切换均正常。
以后每轮即使某天 `?e=` 再超时，也会沿用上次归档而不是让该日消失。
